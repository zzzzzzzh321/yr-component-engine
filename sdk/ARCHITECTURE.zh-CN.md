# Mod SDK 架构与扩展指南

## 当前开发候选与保留交付

保留交付为 0.7.0。当前源码的 0.11.0 / config11 / state1 仍在集中验收，下文的 0.7.0 配置说明保留为对应版本的记录；不能以它替代候选版本的接口定义。

生产配置按完整机制外置：组件解释组、前置、工厂来源与控制字段，宿主在接纳时验证并绑定冻结资源；运行中的计数、工厂队列、升级槽、国家来源和已取得计划仍归各自原所有者。`configure_boundary` 是通用配置生命周期能力，独立于生产目录：普通场景清空，类型重建由组件保留自身全局子状态，读档不重放。原生 Rules 注册表只暂存真实读取历史和同一组件的不透明种子，成功绑定后立即清空已消费历史，避免加载失败重试时从旧世界覆盖新状态。

护甲扩展通过独立 `armor_resource` 查询发布目录、对象/地形绑定和弹头记录。物理配置阶段保留 BeforeTypeData、对象实际读取与弹头无节访问的区别；最终阶段只查询冻结结果。宿主验证目录和引用后原子绑定不可变投影，原 `ArmorId`、交互查询和伤害算法继续作为共同消费者。读档从原组件和配置重建投影，投影不另存一份可编辑目录。SDK 对象事实使用绑定编号对应的正式名称，弹头事实限定在已初始化的记录范围。

候选新增的职责如下：

| 内容 | 插件拥有 | 引擎拥有 |
| --- | --- | --- |
| `match_rules` | 生存、隐形与现有倍率/箱子规则的冻结策略 | 原有计数、胜负、隐形时钟与数值机制 |
| `effect_resource` | 各类对象及弹头的冻结效果描述 | 验证并缓存描述、绑定动画资源 |
| `effects` | 从只读事实生成有序的生命周期操作 | 校验操作，写入唯一效果列表，维护动画引用与派生倍率 |
| 类型策略 | `KeepAlive` 与 `Cloakable.Allowed` 的配置解释 | 原有对象身份、所属方、捕获/转形与生命周期 |

效果没有第二份插件持久列表，也不借用护盾状态。生命周期计划明确区分擦除实例与释放动画的顺序；数值、动画、永久箱子奖励和隐形阶段继续走原有所有者。不同对象类别中的同名类型按实际类别绑定。

正式新局加载使用 `Program::load_with_registries`，传入每个物理 Rules 读取阶段实际可见的资源目录；不能用最终目录代替之前的读取点。手工与生成地图在最终 Rules 后、构造前共用 `bind_scenario_gameplay_resources`；保存恢复采用同一入口的 Saved 分支，核对原组件身份并重建派生资源，不重新解释当前 INI。

API v1 / WIT 名称保持不变只表示消息通道未更名；新钩子、宿主能力和完整世界存档布局仍有版本边界。旧存档保留旧引擎及原组件，不通过补默认字段假装完成二进制存档迁移。

一个作品选择一个可选的 WebAssembly 功能组件，参考组件包含各功能代码，通过作品 INI 配置本局行为。护盾、武器弹药成本、装填数量、低弹量武器选择和手动操作限制都在同一组件内。0.7.0新对局安装后四个已外置Ares模块默认启用，护盾和自定义过载仍需显式开启。原版不声明组件，走原有引擎流程。

插件的实现与开发工具在相邻的 [plugin-dev 独立工程](../../plugin-dev/README.md)维护，使用自己的 workspace 和锁文件；[开发指南](../../plugin-dev/sdk/dev-kit/README.zh-CN.md)中的标准 Cargo 命令不依赖引擎源码。编译依赖限于固定版本的 SDK API、WIT 快照和插件自身的 Rust 依赖，Host 具体服务在运行时由引擎提供。引擎仓库的 `sdk/api` 与 `sdk/wit` 是契约的权威定义；扩展协议时先更新它们与引擎接入，再同步独立工程的开发快照。

工作目录中的引擎与插件工程独立维护：

```text
工作目录/
├── engine/
│   ├── sdk/
│   │   ├── api/                 # 权威请求、计划与公共类型
│   │   ├── wit/                 # 权威通信契约
│   │   └── runtime/             # 宿主运行时
│   └── src/mod_sdk/             # 资源接纳与模拟接入
└── plugin-dev/
    ├── sdk/
    │   ├── api/                 # 固定版本开发快照
    │   ├── wit/                 # 固定版本开发快照
    │   └── package/             # 通用打包工具
    └── plugins/vera20k-ares/src/
        ├── component.rs         # 入口与组合
        ├── support/             # 共用Host与编码
        └── features/
            ├── defense/shield/  # 护盾与过载
            ├── units/           # 手动操作限制
            └── weapons/         # 弹药、装填与低弹量选武器
```

第一份插件发布为 `vera20k-ares.wasm`。Cargo原始core制品为 `vera20k_ares.wasm`；通过打包器的 `--program vera20k-ares.wasm` 指定发布名。内部组件标识继续使用 `vera.reference-gameplay` 0.7.0、配置版本5、状态版本1，API v1与WIT不变。文件名不代表完整Ares兼容；已有Phobos护盾与自定义过载示例保留。

超级武器扩展将来归入插件的 `features/superweapons` 领域，当前没有创建该模块，也未提供超武注册或发射回调。

## 从引擎到功能的调用路径

```text
引擎原有 Rules / 对象构造 / 伤害 / AI 更新阶段
  → src/mod_sdk.rs：稳定入口
  → assets.rs：接纳作品或恢复原组件
  → program.rs：冻结配置、准备请求、调用运行时
  → sdk/runtime：创建新实例、限制执行、校验返回计划
  → plugin-dev/plugins/vera20k-ares/src/lib.rs：WIT 导出与消息解码
  → 插件 component.rs：按回调分派
      ├─ features/defense/shield：护盾与过载
      ├─ features/units/manual_control.rs：手动操作限制
      └─ features/weapons/
          ├─ ammo_cost.rs：每发弹药成本
          ├─ reload.rs：普通/空仓装填数量
          └─ empty_weapon.rs：低弹量武器选择
  → 引擎 simulation.rs：在原阶段提交计划
```

插件通过 `support` 调用只读宿主服务，宿主适配位于引擎的 `host.rs`。配置仍使用引擎已有的 INI 读取器，伤害数值计算仍调用引擎已有的公共算法；插件不复制解析器或伤害内核。

## 每一层负责什么

| 层 | 职责 | 不应放入的内容 |
| --- | --- | --- |
| `sdk/api` 与 `sdk/wit` | 双方约定的请求、计划、版本、能力边界 | 具体护盾或弹药规则 |
| `sdk/runtime` | 组件加载、受限执行、消息校验 | 游戏对象、INI 业务解释 |
| 引擎 `mod_sdk/program.rs` | 原始组件、摘要、manifest、冻结配置；可重建的执行缓存 | 具体功能算法、真实生命值副本 |
| 引擎 `mod_sdk/assets.rs` | 资源声明、摘要验证、存档组件身份匹配、重建武器和对象类型派生策略 | 回调算法 |
| 引擎 `mod_sdk/host.rs` | 可信的配置读取、目录和数值服务 | `ShieldType`、`VeraOverload` 等功能语义 |
| 引擎 `mod_sdk/simulation.rs` | 转换当前游戏事实、调用组件、提交结果或记录故障 | 另写一份护盾逻辑 |
| 插件 `lib.rs` | 对接 WIT、解码、检查回调名称 | 功能配置和游戏算法 |
| 插件 `component.rs` | 声明本组件、配置封装、显式调用顺序 | 护盾如何吸收伤害 |
| 插件 `features/*` | 各自的配置和决策；有状态功能管理自身状态 | 直接修改引擎对象、联网或读取磁盘 |
| 插件 `support/*` | 通用宿主调用、数值编码 | 特定功能的键名和默认值 |

引擎根入口通过重导出保留原有路径，调用方继续使用 `mod_sdk::Program`、`mod_sdk::attach_entity` 等。`Program` 的字段保持私有。现有公开的 `Program::load` 仍保留；需要类型目录的正式加载路径使用 `load_with_types`。

## 公共层组织规则

各功能共用一份公共层。插件侧宿主服务统一在 [support/host.rs](../../plugin-dev/plugins/vera20k-ares/src/support/host.rs) 的 `Host` 中声明，通过 `support` 导入；护盾、弹药及后续功能不各自复制一套 Host。Rust 的 `trait Host` 在这里相当于 C++ 中提供抽象调用契约的接口类，文件后缀为 `.rs`。

| 公共内容 | 唯一维护位置 |
| --- | --- |
| 插件可调用的宿主服务、WASM调用适配、配置视图与节读取包装 | `support/host.rs`，目前包含 `Host`、`WasmHost`、`ConfigView`、`Section` |
| 通用数值序列化 | `support/codec.rs` |
| 引擎与插件共用的请求、计划、版本及基础类型 | 引擎 `sdk/api` 为权威定义，独立工程使用固定版本快照；共用倒计时沿用其中的 `timer` 模块 |
| 武器成本、类型装填与低弹量选择的静态策略协议 | `sdk/api/src/resource.rs` |
| 跨WASM边界的导入与导出契约 | 引擎 `sdk/wit/gameplay.wit` 为权威定义，独立工程使用匹配快照 |
| 宿主服务的引擎端实现 | 引擎 `src/mod_sdk/host.rs`，转交已有读取器和领域算法 |

`Host` 集中声明插件实际需要的通用服务，如配置读取、类型目录和共用伤害计算。具体键名、默认值、护盾吸收算法或弹药成本政策仍放在对应功能模块；通用读取器接收节名和键名，不直接认识 `ShieldType` 等具体玩法。请求上下文与返回计划继续归 `sdk/api`，不因它们也被多处使用就混进 Host 服务接口。

当前公共代码规模较小，保持上述结构。以后某类服务的实现变复杂时，可以按职责拆分实现文件，同时保留清楚的公共入口；新增服务时同步接通协议、插件适配、运行时和引擎实现。只有功能确实需要的能力才进入公共接口，不预先填入大量空方法。

目录按领域归类，再按完整机制划分模块：防御领域的护盾有配置、持续状态与多个回调，因此使用文件夹；武器领域的三个静态策略各用一个文件。各模块都通过同一 `Host`、`ConfigView` 和 `Section` 访问已有服务。本次新增 `type_resource` 是 `evaluate` 的可选查询消息，没有新增 Host 服务或 WIT 导入。

## 配置、状态和缓存各有一个所有者

- **功能配置**：护盾模块拥有护盾目录、全局默认值、对象/弹头绑定和过载设置；`ammo_cost`、`reload`、`empty_weapon`分别拥有武器成本、装填量和低弹量选择配置，`manual_control`拥有手动操作限制配置。组件层只组合它们。配置阶段结束后冻结，对局中只读。
- **对象状态**：护盾模块拥有护盾值、四个恢复倒计时、热量和过载倒计时。引擎仅保存不透明字节，不另维护一套护盾状态。三种武器资源策略不需要独立对象状态，真实弹仓、装填时钟和最终选用武器仍由引擎原有所有者维护，因此没有为它们增加通用多功能状态容器。
- **显示数据**：插件输出通用进度条和染色投影，由引擎显示；投影不作为游戏状态权威。
- **派生策略**：Rules 的武器和对象类型策略来自冻结组件配置；加载和读档时重新绑定，不成为第二份可编辑配置。正式开火、装填、选武器的热路径读取这些不可变投影，不逐对象进入WASM。
- **执行缓存**：编译后的 Wasm 可丢弃并重建，不进存档或联机校验。每次回调仍创建新的实例，不依赖 Wasm 全局变量保留状态。

组件层是功能启用的唯一所有者。0.7.0仅在新对局的空初始配置入口，将`AresAmmo`、`AresReload`、`AresNoAmmoWeapon`、`AresManualControl`置为启用，`Shield/Overload`仍关闭；这不是宿主对所有组件的默认。历史非空配置继续按原格式解码，不通过修改反序列化缺省给旧对局补入新选择。各标签自身的默认值不变，例如四个手动限制仍默认`no`。

`[VeraFeatures]`逐Rules层读取，显式`no`可独立关闭相应模块，缺失、空值和无效值保留前一选择，后层有效`yes`可再开启。最终校验Overload依赖Shield，并配置已启用模块；全部成功后才发布冻结结果。护盾目录在未开启时仍累积，以支持后层开启。

`weapon_resource`在AresAmmo关闭时不发布策略；`type_resource`按实际对象类别组合已启用的装填、武器选择和输入策略，飞机排除装填策略但可使用低弹量选择策略。手动模块启用时，即使未设限制标签也发布显式false的输入策略，避免恢复时落回当前INI中的内置决策；关闭该外置模块不等于关闭宿主内置`ares`构建特性。Shield关闭时对象事件返回空状态和空显示投影。Overload的启用布尔值显式传给护盾算法，不在功能配置中另存一份。战斗各阶段、计时器和随机数顺序沿用现有调用点。

## 添加下一项功能

先判断现有接口是否已经提供所需事实和可提交结果。

1. **已有能力足够**：在 `features` 增加本功能模块，使其拥有配置和决策；在 `component.rs` 的配置阶段和相关回调中显式接入。功能启用项写入 INI，并随冻结配置保存；不要用 Cargo feature 代替玩法选择。`lib.rs`、Wasmtime 运行时和引擎通常无须改动。
2. **需要新的通用能力**：先扩展 `sdk/api` 的上下文/返回计划及其验证，再在引擎真正拥有该状态的模块接入。只有新增宿主服务时才需要改 WIT 导入。引擎保留通用操作，兼容写法与功能算法留在插件。
3. **同一回调有多项功能**：在组件层明确先后关系、伤害如何传递和显示如何合并。当前没有通用多功能状态容器，也没有自动冲突合并。新增第二项有状态功能时，应先设计有版本的状态封装，再增加读写双方与存档测试，不能直接覆盖另一功能的字节。

例如修改“每发消耗两颗弹药”为“消耗三颗”，修改 `features/weapons/ammo_cost.rs` 的策略或其配置解释，再构建组件即可；装填数量修改 `reload.rs`，低弹量武器策略修改 `empty_weapon.rs`。具体Ares标签由对应模块解释，引擎只接收通用策略。开火检查、扣弹、装填和武器选择仍走原引擎所有者。若希望实现“护盾受到伤害后给另一辆车回血”，目前的返回计划无法表达它；应设计受校验的通用跨对象效果，不能绕过权限直接写对象。

各模块通过组件层显式组合，当前没有动态注册总线、依赖解析或通用继承框架。多个作者可以维护各自的功能目录；一个作品的组件层负责选择、编译和确定顺序。有第二个独立组件真正需要共用代码时，再把 `support` 提成单独的 SDK guest crate。

## 兼容边界

统一参考组件声明`vera.reference-gameplay` 0.7.0，config_version=5，state_version=1；API v1、WIT包名不变，组件包含六种回调。四个基础回调之外，`weapon_resource`按武器、`type_resource`按对象类型和类别查询静态策略。后两种回调均为可选能力。冻结配置包含六项功能选择及各模块配置，0.7.0不改变配置、护盾状态字段或浮点位编码。功能选择与配置原始字节一起进入存档和联机校验，不接受对局中读取当前INI或应用新默认来覆盖。

旧二进制组件及其冻结配置保持各自原有行为；没有声明新查询的组件不会收到该查询，对应策略为空。它们不认识的新开关不能靠修改INI获得。包括0.6.0在内的旧组件不会因0.7.0的新默认而自动改变，也不进行跨组件迁移。

源文件搬动或重新编译可能改变组件的SHA-256。存档保存原组件字节、声明与冻结配置，读档仍要求当前作品资源的组件摘要与存档完全一致，随后使用保存的原组件及配置重建派生策略；不能因存档带Wasm就省略当前资源的身份匹配。旧存档应保留原组件及声明，相同数据格式不代表可以把旧局组件直接换成新构建。本版没有热替换或状态迁移。宿主仍需支持`use_weapon_rof`、可选`input`策略与完整建筑延迟索引；API v1相同不代表旧宿主具备这些能力。

验证入口包括插件行为测试、真实Wasm与原生配置读取器的集成测试，以及原版/兼容护盾/过载护盾/弹药/零售地图的正式引擎探针。默认安装验证须省略四个Ares启用开关，核对原标签、已接入的无标签修复、显式关闭与层次保留，以及旧/新冻结配置恢复；不能只比较策略字段。`sdk_ini_selection_is_layered_frozen_and_restored_with_the_program`通过真实INI读取器检查分层开关、依赖、禁用、保存与恢复。结构迁移时，`sdk_refactor_preserves_`可比较同一接口与配置版本下纯移动或重构前后的制品，需另设baseline/candidate路径；0.7.0改变新对局默认，不应要求它与0.6.0的冻结配置相等。构建与命令行说明见[中文README](README.zh-CN.md)和[弹药示例](../../plugin-dev/plugins/vera20k-ares/AMMO.zh-CN.md)。

以上仍是实验版 SDK，不代表完整 Ares/Phobos 兼容，也没有完成大规模性能和各桌面平台的验证。
